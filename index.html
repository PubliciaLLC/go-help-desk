Release

New in 1.3.0

The biggest release since 1.0. Here is what changed.

Pull, don't build

Published images for amd64 and arm64. docker compose up -d pulls them, and nothing is compiled on your machine. Quick start →

Passkeys and an Account page

Passkeys and hardware security keys work as a second factor beside TOTP, used after the password. A new Account page changes your password and manages your factors. Second factor →

OpenID Connect, now documented

Sign in with an OpenID Connect provider, beside SAML and local accounts. It is set up under Admin → Settings → Authentication. It has shipped since 1.1.1, but was not documented on this site before 1.3.0. New in 1.3.0: a refused sign-in says why on the login page, and an account whose provider wraps its email address is matched to the right account. OIDC setup →

Guest submission

Guest submission works end to end. A visitor files a ticket without an account, then replies through a private link. Attaching a file is possible only through the API. The guest page has no upload control, and that is not available in 1.3.0. The link becomes read-only when the ticket closes. Read how it works →

Closed means closed

Closed tickets are read-only and stay closed by default. The way on is a linked follow-up ticket. Resolved tickets close automatically once the reopen window passes. Read the lifecycle →

A readable audit log

Each ticket has an activity feed, and administrators get a searchable audit view. The log is kept forever unless you set a retention period. Read about the audit log →

Webhooks for Slack, Teams, Discord and JIRA

Each enabled webhook receives the events it subscribes to, in the payload format you choose. Webhooks are sent once and are not retried. Read about webhooks →

Works on a phone

Staff can triage, and reporters can file and follow requests, from a phone. Administration stays on the desktop. What's new →

Attachment security

Uploads are checked against their content, optionally scanned by ClamAV, and optionally looked up at reputation services. Files are download-only, and nothing is rendered in the browser. Read how it works →

Features

Everything a support team needs

From basic ticketing to enterprise SSO — all in one binary.

CTI Classification

Organize tickets with a three-level Category → Type → Item cascade, inspired by Remedy. Each level filters the next.

Ticket Lifecycle

Configurable statuses, a reopen window for resolved tickets, and automatic closure. Closed is read-only by default; a linked follow-up ticket carries on the work.

Roles & Groups

Admin, Staff, and User roles. Group-based staff scope tied to CTI categories — each team only sees what's theirs.

SSO & MFA

Local accounts, SAML 2.0 and OIDC sign-in. Administrators keep password sign-in when SAML login is on. A second factor by authenticator app (TOTP) or passkey / security key.

Linked Tickets

Connect tickets as related, parent/child, caused-by, or duplicate-of — across any status, including closed.

SLA Tracking

Optional SLA targets per priority and category. Track response and resolution times against your commitments. Timers pause while a ticket is in the Pending status.

Email & Webhooks

Email requesters about ticket events via SMTP, queued and retried on failure. Staff are not emailed about ticket events. Staff email is not available in 1.3.0. Outbound webhooks for Slack, Teams, Discord and JIRA formats, or raw JSON, sent once without retry.

REST API & MCP

Full REST API with API key and OAuth2 client-credential auth, documented as OpenAPI 3.1 in the API Reference. Plus an MCP server so AI assistants can create and manage tickets as native tools.

Plugin System (planned for v2)

A plugin system is planned for v2. Plugins cannot be installed in 1.3.0.

Canned Responses

Reusable reply templates scoped globally, by category, or by category and type — inserted into any reply with one click.

Full-Text Search

Relevance-ranked Postgres full-text search across subject and description, word-prefix matched as you type — no more guessing the exact substring.

Attachment Security

Every upload is detected, hashed and compared against the name it arrived under. ClamAV scanning, an optional quarantine tier, and an optional hash lookup at four reputation services. Nothing is ever rendered in the browser. Read how it works →

Guest Submission

Anyone can file a ticket without an account and follow it through a private emailed link. No password, no signup. The link is scoped to one ticket, replaced whenever the help desk writes back, and read-only once the ticket closes. Read how it works →
