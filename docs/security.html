Security

Every security issue we have found or been told about is published as a GitHub advisory, with the versions it affects and the release that fixes it. This page lists them, says how to report one, and points at the deeper writeups.

Run 1.2.0 or later. Everything below is fixed in v1.2.0, including for anyone still on v1.1.1. Upgrading is not a drop-in swap — credentials created in the 1.1.1 admin UI stop working, and everyone is signed out once. Read the upgrade notes first →

Advisories

Newest first. Severity is ours, assigned with GitHub's CVSS calculator.

Critical

Authentication and authorization bypasses

GHSA-p2wx-wvfr-7h3p · affects ≤ 1.1.1 · published 15 Sep 2026

Eight defects in one advisory. MFA could be defeated with a password alone; signed-in users could read and write tickets they had no access to; API key and OAuth scopes were never enforced, so any credential acted with full authority; no credential could be revoked; and any signed-in user could stop the server.

Fixed in v1.2.0 · Read the advisory →
Medium

A regular user could read and post any ticket's replies

GHSA-q9g5-2fp5-hmmx · affects ≤ 1.1.0 · published 15 Sep 2026

Broken function-level authorization: handleListReplies and handleAddReply omitted the ownership check their sibling handlers enforced, so any signed-in user could read any ticket's replies — including internal staff-only notes — and post replies to other people's tickets.

Fixed in v1.1.1 · Read the advisory →
Critical

Unauthenticated MCP ticket access via /mcp/

GHSA-5g72-m483-3v63 · affects 1.0.1 · published 15 Sep 2026

The MCP endpoint served ticket reads and modifications with no authentication at all.

Fixed in v1.1.0 · Read the advisory →
Critical

MCP server allowed impersonated replies and assignment hijack

GHSA-26xr-728v-639v · affects ≤ 1.1.0 · published 13 Sep 2026

With no authentication on the MCP server, anyone who could reach it could read tickets, post replies as somebody else, and reassign work.

Fixed in v1.1.1 · Read the advisory →
Critical

MCP server exposed unauthenticated read and write to all tickets

GHSA-2x4f-j4jv-m2cm · affects ≤ 1.1.1 · published 12 Sep 2026

The same class of exposure as the two above, covering every ticket in the instance.

Fixed in v1.2.0 · Read the advisory →

Reporting a vulnerability

Please do not open a public issue. Report privately through GitHub:

Report a vulnerability privately →

Include as much as you can: what the vulnerability is and what it lets somebody do, how to reproduce it, the affected versions, how the instance is deployed, and any fix you would suggest.

Supported versions

Security fixes are issued for the 1.3 release line only: 1.3.0 and its patch releases. Earlier versions, 1.2 included, are not backported. Every advisory above affects at least one of them, so anything below 1.3 is not merely unsupported but known to be vulnerable. Upgrade to 1.3.
